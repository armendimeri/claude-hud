## What was built

| Module | Role |
|---|---|
| `reader.mjs` | `createHistoryReader({summarizeTool, key?, instance?, limits?})` returns `{readHistory, instance}`. `readHistory({source, selection, before?, after?, signal})` returns `{entries, before, after, gap}`, which is the CONTRACTS P4 → P8 seam. It scans byte blocks backwards (initial and older pages) or forwards (catch-up), splits lines on LF before decoding and decodes only complete lines. It strips CRLF and BOM, folds repeated blocks and enforces the limits. |
| `cursor.mjs` | Opaque cursor: base64url JSON plus a 16-byte HMAC-SHA256, capped at 2 KiB. It binds the runtime instance, the entity (provider plus `[sessionId, agentId]`), the file generation, the direction, the offset, a skip flag for an oversized record, a 32-byte anchor hash and up to 8 fold keys. |
| `claude.mjs`, `codex.mjs` | The visible allowlists. The module headers record the merge precedence. |
| `source.mjs` | `openHistorySource(record, {roots})`: realpath, containment in the configured roots, the conflict check, open, and a check that the open handle is the file the path names now. It returns a generation and a close-once `close`. `createHistoryService({resolve, readHistory, roots})` is the reference resolve → open → read → `finally close` composition. P8 can adopt it or replace it. |
| `errors.mjs` | `HistoryError` with stable `{code, message}` and an HTTP `status`. Messages contain no paths. |

Limits are 40 entries, 512 KiB read per call (anchor reads included), 64 KiB blocks and 8 KiB per entry with the marker ` … [truncated]` plus `truncated: true`.

**Merge precedence.**
- Claude: a user record folds by `uuid`. An assistant text block folds by `message.id` plus its text. A `tool_use` block folds by its block id. Within a page the first occurrence in source order wins. Across a page boundary the copy already shown wins, using the 8 boundary fold keys in the cursor.
- Codex: the canonical family is `event_msg` `user_message` and `agent_message`. `response_item` messages are never shown. Tool calls fold by `call_id`. Event messages have no id and never fold, so two identical prompts in a row stay distinct.

Cases covered by `tests/operator-history.test.mjs`:
- **Exact allowlist on real-shaped fixtures.** The fixtures include a Claude parent, a separate Claude child and an older in-file sidechain record. They also include a Codex sibling, a separate Codex child, meta/instruction records, reasoning, tool results, repeated blocks, multibyte text, CRLF and partial last lines. Every private canary is asserted absent everywhere except its own page.
- **Pagination and appends.** Backward paging runs in 40/40/20 steps. Ids are stable across repeated walks, timestamps are equal throughout, and two identical messages stay distinct. A repeated block split across a page boundary is shown once in both directions. A late append during pagination appears only on the forward page. A partial UTF-8 record is retried intact after its append.
- **Stale cursors.** Rotation by rename returns 409. So does in-place truncate-and-rewrite (caught by the anchor) and truncation below the offset (caught by the size check).
- **Oversized records and giant tails.** An oversized record is skipped whole backwards and forwards, with at most 512 KiB read per call. A giant unterminated tail does not block older history. A window of only filtered records returns a continuation with zero entries.
- **Cursor checks before any read.** A cursor from a child, from a same-label sibling, in the wrong direction, tampered with or overlong is rejected with zero reads. Supplying both cursors returns 400. A cursor from an earlier runtime instance returns 409.
- **Handle ownership.** The reader never closes the borrowed handle (spy count 0). The service closes every handle exactly once on success, on a cursor error and on abort.
- **Missing child and source checks.** A missing child is unavailable and the parent file is never opened in its place. An extra configured root is readable. A file outside the roots is refused, and so is a directory junction inside a root that points outside it. Junction creation worked on this host, so that assertion ran. Two real files for one identity are a conflict; two spellings of the same file are fine.
- **No silent empty pages.** Unknown, malformed (invalid JSON or invalid UTF-8) and response-item-only Codex records produce explicit gaps. An empty file is an empty success.
- **Static independence check.** `live`, `publish`, `runtime`, `tail-reader`, both source tailers and `http/server` never import history, and the history modules never import the live runtime.

## Contract additions for the P1 coordinator

These are not edits. CONTRACTS.md and the fixtures are unchanged. I propose adding them to the fixtures:

1. **Gap shape.** The page `gap` is `null | {records: n, reasons: {compacted?, malformed?, oversized?, overflow?, unknown?: n}}`. The contract shows only `null`.
2. **Truncated entries.** An entry may carry `truncated: true`, alongside the text marker.
3. **Cursor directions.** The initial page returns both cursors. An older page returns `after: null` and a forward page returns `before: null`. The browser should keep the initial page's `after` for catch-up. `historyPages.older` in `private.mjs` shows a non-null `after`, which is only a fixture.
4. **Error codes.** `bad_request` (400), `invalid_cursor` (400: tampered, other entity, wrong direction), `stale_cursor` (409: generation, truncation, rewrite, earlier instance) and `unavailable` (404, the same text as `errors.unavailable`).
5. **Provider value.** `source.provider` is the transcript format, `'claude' | 'codex'`, which matches the snapshot `agent`. It is not the model provider (`anthropic`/`openai`/`bedrock`) in `private.mjs` targets. P8 maps a target to the format, and a Bedrock Claude session reads as `claude`.

## Limitations and unverified

- **Record shapes are synthetic.** They follow the repository's existing tailers and known provider formats. They were **not** checked against real Claude Code 2.1.312 or Codex 0.171 files, because the lane rules forbid reading the owner's histories. To verify, run a throwaway synthetic session under a temporary `CLAUDE_CONFIG_DIR`/`CODEX_HOME` (P5/P6 or P11) and feed its file through `readHistory`.
- **Older Codex rollouts.** A rollout that predates `event_msg` messages shows an `unknown` gap on backward pages only. On forward pages the heuristic is off to avoid noise while a turn is half written.
- **Folding limits.** A cumulative-streaming format, where a later line repeats a block with longer text, is not folded. Cross-page folding covers only the 8 entries next to the boundary.
- **Platforms and Node versions.** Only Windows and Node 22.12.0 were run. POSIX and Node 26 were not.
- **Not run.** `node hud.mjs selftest` (out of P4 scope and it may read real profiles), the browser smoke test and the archive checks. No pages were opened in a browser.
- **Windows stat finding.** On Node 22.12.0, path `fs.stat(..., {bigint:true}).dev` is `0n` while `FileHandle.stat` reports the volume serial. The opener compares `dev` only when both sides are nonzero.

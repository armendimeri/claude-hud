## Interface

`mountInspector(host, {selection, store, client, onClose, signal, ...}) => {select(selection), close(), root, inspect()}`, the frozen P7 to P3 shape. Additive optional members, all documented in `panel.mjs`:

- `getDiscreet()` and `subscribeDiscreet(fn)`: turning discreet on closes the panel (reason `discreet`), aborts reads, drops rows, drafts, receipts and DOM. Focus is not restored while discreet.
- `restoreFocus(selection)`: host returns the element to focus on close. Without it the panel looks for `[data-entity-key="<JSON [sessionId,agentId]>"]` (same key as `entityKey` in `cockpit/projection.mjs`), then the element that was focused at mount.
- `onClose({reason, selection})`, reasons `close`, `back`, `escape`, `discreet`. An outer `signal` abort closes silently without calling `onClose`.
- The client seam is exactly `history`, `capabilities`, `submit`, `receipt` from CONTRACTS. A public-only client that rejects with `{code:'unavailable'}` or returns `reason` works: the panel shows the reason and a disabled composer.

Behaviour decisions to know about:

- Public header and activity render synchronously. Private reads start only on **Show conversation**. Once pressed, the open state carries across ordinary switches while the panel stays open, and ends on close or discreet.
- A new selection aborts the previous reads (generation plus AbortController) and drops the previous entity's rows. A delivery already sent is not aborted by a switch (the provider may have it); its receipt is stored under the entity it was sent from and shown only there.
- Drafts are in memory, keyed by `[selectionKey, turnId, requestId, kind]`. They survive switches, and are cleared on close, discreet, an acknowledged send, a request closed elsewhere (notice shown), and a steer draft whose turn ended (notice shown). I chose discard over retarget, so a finished-turn draft is never silently re-sent as a prompt.
- Capabilities and catch-up refresh only when the entity's status, needs-you time, current tool, running-subagent count or end time changes in the public store, never on a clock tick.
- After a transport failure a send shows "Delivery unknown", keeps that request's controls disabled and offers **Check status**, which calls `client.receipt` with the original action ID. Nothing retries automatically. Acknowledged text is "Delivered to the session." The word "resumed" is never shown.
- History uses the P4 cursor rules: initial `after` is kept for catch-up, older pages only change `before`. A `stale_cursor` error becomes a visible "conversation moved on" gap with **Load a fresh page**.

## Limitations and notes for P7 and the coordinator

- **Escape:** the panel listens on `document` in the capture phase, calls `preventDefault` and `stopPropagation`, and closes. A shell listener registered on `window` in the capture phase would still run first, so P7 should have the shell check `event.defaultPrevented` too.
- The panel does not own placement: P7 gives it a host element and a width (400 or 480 px, or full width under 600 px) and decides overlay versus side. At under 600 px viewport width the panel switches itself to the sheet layout, via `matchMedia`, and shows **Back to map**.
- P7 must register `src/web/inspector/inspector.css` and the three modules in the allowlist and package, and exclude `src/web/inspector/harness/`. Static import graph of `panel.mjs`: `components/lifetime.mjs`, `dom.mjs`, `format.mjs`, `status.mjs`, `sessions.mjs`, `data/selectors.mjs`, `inspector/state.mjs`. `inspector.css` needs the foundation tokens already loaded.
- Closed-request and finished-turn drafts are discarded with a notice rather than retargeted; change only if the owner wants a "move draft" action.
- The panel never fetches by itself on a timer; the catch-up cadence while visible (P7-01) is driven by the public store signal described above. P7-01 may add its own bounded timer through the same `client.history` seam if the public signal proves insufficient.
- `delivery-unknown` also blocks that request's own controls until checked. A different request on the same session is not blocked.
- Permission cards never show a free-text field. A pending request with no matching write capability shows no composer, only the question or permission card.
- Client-side action expiry is not tracked: expiry is learned from a 409 or a fresh capabilities read. If the server adds an expiry timestamp, add it to the capabilities DTO and fixtures first.

## What was built

| Piece | Behaviour |
|---|---|
| Wiring (step 1) | The live and demo engines return an `operator` descriptor. The live descriptor carries the registry `findSession`, the redacted `summarizeTool`, the Claude `projects` roots and the Codex `sessions` roots. The demo descriptor carries only `kind: 'demo'`. `createRuntime` wraps the descriptor in a lazy slot. `routes.mjs` is dynamically imported on the first `/api/operator` request. The CLI passes `runtime.operator` to `createHttpServer`. The `operator` option is optional: the `cockpit-baseline.mjs` test doubles still construct the server without it, and every private path then returns 404. `createLiveRuntime(config, {operator})` and `createDemoRuntime(config, mode, {operator})` accept overrides (`open`, `resolveAdapter`, `createDispatcher`, `clock`, `verifyAcl`) for tests and for P11. `live.mjs`, `runtime.mjs` and `server.mjs` still never import `sources/history`, and P4's static independence test passes. |
| Pairing (step 2) | `node hud.mjs operator pair [--port=<n>]` fetches `{instance, port, store}` from the loopback-only `GET /api/operator/instance`. It then writes `pair-<port>.json` to the per-user operator folder, containing `{v, instance, port, digest: sha256(code), expires: +5 min}`. The write is atomic (temp file, then rename). The 256-bit code is printed only by the CLI. `POST /api/operator/pair {code}` is serialized in-process. It reads the ticket, checks instance, port and expiry, and compares the digest in constant time. It consumes the ticket with an atomic rename, then re-reads the claimed file to detect a replacement. Only then does it issue the session. Limits: 5 wrong codes delete the ticket, and there are at most 20 attempts per minute (429). |
| Session | Cookie `hud_operator_<port>=<random 256-bit>; Path=/api/operator; HttpOnly; SameSite=Strict; Max-Age=…` with no Domain, so it is host-only. `GET /api/operator/bootstrap` (cookie, marker header, same-origin) returns `{token, epoch, expiresAt}`. Sessions live only in memory: 12-hour lifetime, at most 16 sessions, cookie stored as its SHA-256. The epoch is the random runtime instance, so a restart invalidates every cookie, ticket and cursor. |
| Request checks | Every private route requires a loopback socket peer, a Host of exactly `127.0.0.1:<port>` or `localhost:<port>`, no proxy headers (`Forwarded`, `Via`, `X-Forwarded-*`, `X-Real-IP` and similar), the `X-HUD-Operator` header, `Sec-Fetch-Site` equal to `same-origin` when the header is present, and an Origin equal to `http://<Host>` when present. Origin is required on POST. Data routes need the token in `X-HUD-Operator`. HEAD and OPTIONS return 405 and no CORS header is ever sent. Every response is JSON with `Cache-Control: no-store` and never redirects. The hook route's rules are unchanged. |
| Resolver (step 3) | `createLiveResolver` authorizes the selection against the current public snapshot: the session must be published, and an agent must be among its published subagents. For a Claude child it accepts both aliases (agent id and Agent tool-use id) when they lead to the same subagent object. Two different subagents under one alias means unavailable. The subagent must have its own tail owned by this session, and the file must be named `agent-<verified agentId>.jsonl`. It passes `native.agentId` to P4. A Claude session also lists same-named transcripts in the other configured profiles, so `openHistorySource` refuses two real files as a conflict. A Codex child must be published under the root and have a recorded `codexParent` chain to that root (depth ≤ 8, no cycles, every ancestor a Codex session, no `codexInternal`). Targets are `{selection, provider, nativeSessionId, connectionGeneration: null}`, plus `nativeAgentId` for a Claude child. Providers are mapped as `codex → openai` and Claude to `bedrock` or `anthropic` (from the snapshot). The format is checked against the provider map in CONTRACTS. |
| History routes | `GET /sessions/{key}/history?before=|after=`. The key is canonical base64url JSON `[sessionId, agentId]` of at most 2 KiB. Supplying both cursors returns 400 before any file is opened. Each request is resolved, opened, read and closed through P4's `createHistoryService`. Each request gets `AbortSignal.any([service lifetime, client disconnect])`. Faults are mapped per request: `HistoryError` gives its own status and code, abort gives 503 `closing`, and anything else gives 500 `internal`. Only the error class and code are logged, never content or paths. At most 16 requests are in flight (503 `busy`). |
| Capabilities and actions (step 4) | With no adapter, `GET /capabilities` returns `{epoch, revision:'observed', actionWindow:null, available:['history'], activeTurnId:null, pending:[], reason:'observed_only'}`. With an adapter, its fields are allow-listed and the server's epoch is set. Writes, `actionWindow` and `pending` are dropped unless a dispatcher is registered. An adapter that throws gives 503 `provider_unavailable`, and history keeps working. `POST /actions` checks auth and Origin, then reads a JSON body of at most 16 KiB (413 when larger) and checks for a UUID `actionId` and a string `kind`. It then resolves the target (404 when unknown) and calls `dispatcher.submit(target, command)`. `GET /actions/{uuid}` calls `dispatcher.receipt(target, actionId)` and returns 404 `unknown_action` for null. Without a dispatcher both return 503 `actions_unavailable`. Demo mode never builds a dispatcher or adapter. |
| Shutdown | `runtime.close()` closes the operator slot. The service aborts its lifetime signal and waits for in-flight requests, whose handles close in P4's `finally`. It then clears every session and removes this instance's unused ticket. Last, it calls `dispatcher.close()`. Later private requests return 503. |
| Demo | `createDemoResolver` authorizes against the demo snapshot and returns a synthetic record with no file paths. History is three generated entries built from public fields, with an opaque `demo-…` cursor. No roots, opener, adapter or dispatcher are used. |
| Config | `operatorDir` = `HUD_OPERATOR_DIR`, or else `%LOCALAPPDATA%\claude-hud\operator` on Windows or `$XDG_STATE_HOME`/`~/.local/state` + `claude-hud/operator` on POSIX. The folder is created only by a pairing command or request, never at startup. |
| Private folder | Created with mode 0700. Verification runs before every ticket write or read. On POSIX it checks plain folder, owner uid and no group or other bits. On Windows one PowerShell call lists the owner and Allow ACEs by SID (locale-independent) and accepts only the current user, SYSTEM, Administrators and CREATOR OWNER. **A folder the HUD has just created is first restricted** with `icacls /inheritance:r /grant:r` to exactly those principals. An existing folder is never changed. A failed check returns 503 `pairing_unavailable` with an explanation, while the public HUD keeps running. The CLI prints the same explanation plus the folder path, in its own terminal only. |

## Decisions taken (defaults for the coordinator to confirm)

1. **The HUD restricts the operator folder it creates.** This PC's `%LOCALAPPDATA%` grants a local sandbox group read access by inheritance, and `%TEMP%` grants it modify. A strict check of an unrestricted new folder would always fail. A new folder is therefore made user-only with `icacls`. A pre-existing folder is only verified, never changed.
2. **Error codes added to the P4 set:** `forbidden` 403, `not_paired` 401, `pairing_failed` 401 (one message for wrong, expired, replaced or consumed codes, so there is no oracle), `pairing_unavailable` 503, `too_many_attempts` 429, `method_not_allowed` 405, `unsupported_media_type` 415, `too_large` 413, `busy`/`closing` 503, `actions_unavailable` 503, `provider_unavailable` 503, `unknown_action` 404, `internal` 500. CONTRACTS does not list 405, 415 or 429. They are used for HEAD/OPTIONS, a non-JSON pair and the attempt bound.
3. **The `X-HUD-Operator` header is required on every private route:** `1` on instance, pair and bootstrap, the token elsewhere. A cross-origin request therefore always needs a preflight, which is never answered.
4. **Lifetimes:** sessions last 12 hours and at most 16 are kept. Tickets last 5 minutes (from CONTRACTS).
5. **A write's body is read and checked before the target is resolved.** An oversized action therefore returns 413 even for an unknown target, and the connection never carries an unread body.
6. **`nativeAgentId` was added** to a Claude-child target. The fixture targets show a separate `nativeSessionId` for the child, but a Claude subagent has no session of its own. P9/P11 can use the parent session id plus the agent id.
